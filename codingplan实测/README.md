# Coding Plan 服务横向评测

> **声明**: 以下所有数据均为实测数据，评测时间：2026年4月

## 评测标准说明

为保证评测公平性，所有平台均使用相同的测试任务进行评估。

### 测试任务：Word智能水印溯源系统

测试任务为开发一款"**Word智能数字水印与溯源系统**"工具，具备以下核心功能：

**核心功能需求**：
- **水印嵌入**：为Word文档嵌入唯一、隐蔽、可抗破坏的溯源水印（UID）
- **分析溯源**：从疑似泄露文档中提取并解密水印，还原原始接收者信息
- **密钥管理**：支持多项目密钥的创建、导入、导出、删除

**技术要求**：
- PySide6 GUI界面，支持文件拖拽
- python-docx + lxml 处理DOCX文件
- cryptography 库实现AES-256加密
- SQLite 数据库存储密钥和分发记录
- 五层冗余备份策略（防WPS/Word重写）

**项目规模**：约1100行代码，包含：
- 核心水印模块（嵌入/提取算法）
- 数据库模型（密钥/记录管理）
- UI主窗口（双标签页）
- 安装脚本与依赖管理

---

### 评测维度

| 维度 | 说明 | 权重 |
|------|------|------|
| **完成时间** | 从开始到首次可运行版本的时间 | 30% |
| **请求数** | 完成项目所需的总API调用次数 | 20% |
| **Token消耗** | 完成的输入+输出Token总量 | 20% |
| **首交完成度** | 首次响应的代码完整度、可运行性 | 30% |

---

### 评测方法

#### 1. 完成时间
- 记录从第一个请求到获得首个可运行版本的总耗时
- 不含调试和人工修改时间

#### 2. 请求数统计
- 统计完成项目所需的总API调用次数
- 包括：代码生成请求、文件创建请求、修改请求等

#### 3. Token消耗
- 记录输入Token（任务描述、上下文）
- 记录输出Token（生成的代码）
- 计算总消耗量

#### 4. 首交完成度评估

| 评级 | 标准 | 说明 |
|------|------|------|
| ⭐⭐⭐⭐⭐ | 90-100% | 直接可运行，功能完整 |
| ⭐⭐⭐⭐ | 70-89% | 可运行，存在小问题需微调 |
| ⭐⭐⭐ | 50-69% | 部分可运行，需要较多修改 |
| ⭐⭐ | 30-49% | 仅框架可用，核心功能缺失 |
| ⭐ | <30% | 仅有注释或伪代码 |

## 术语说明

- **RPM**: Requests Per Minute，每分钟请求数
- **RPS**: Requests Per Second，每秒请求数
- **TPS**: Tokens Per Second，每秒生成的Token数
- **Codex**: OpenAI 的代码生成模型版本
- **MCP**: Model Context Protocol，模型上下文协议
